# Adding & Editing Content on the BAES Website — Quick Guide

This guide assumes you've never used this system before. No technical
knowledge needed — just follow the steps.

## Getting started

1. Go to **[yourdomain.org.uk]/admin** in your web browser
2. Click **Login with GitHub**
3. If this is your first time, you'll be asked to authorise access — click
   **Authorize**. You'll need a GitHub account; if you don't have one, ask
   whoever manages the site to send you an invite first
4. You'll land on the **Content Manager** — a dashboard with a menu down the
   left side: Events, Corps Pages, Players, Content Creators, Locations, News

That's it — you're in. You never need to touch anything called "Git",
"commit", "repo", or "branch." The system handles all of that for you in the
background.

## Adding a new Event

1. Click **Events** in the left menu, then **New Event** (top right)
2. Fill in the form:
   - **Title** — name of the event
   - **Discipline** — pick the game(s) from the list
   - **Scale** — how big it is (Unit, Corps, National, International, etc.)
   - **Corps** — only fill this in if it's specific to one Corps
   - **Presence Type** — "Competitive" if we're actually competing,
     "Community/Outreach" if it's just a stall/presence with no competitive
     result (e.g. a recruitment tent at a gaming festival)
   - **Date Status** — if the date is 100% confirmed, pick "confirmed" and
     fill in the date. If it's likely but not certain, pick "provisional"
     and list the possible dates instead. If nobody knows yet, pick "tbc"
   - **Format** — Online, LAN, or In-person
   - **Location** — name and map coordinates, if relevant
   - **Description** — a short write-up, in your own words
3. Click **Publish** (or **Save** if using the draft/review system — see
   below)

## Editing an existing Event, Corps page, etc.

1. Click the relevant section in the left menu (e.g. **Corps Pages**)
2. Click on the item you want to change from the list
3. Edit any field
4. Click **Publish** to save your changes

## Adding a Player

**Important — read before adding anyone:**
- Default to **gamertag only**. Only use a real name, Corps, or photo if the
  player has explicitly agreed and the "Disclosure Tier" is set accordingly
- Never combine real name + Corps + base + schedule in one profile
- Tick **PERSEC/Branding Clearance Confirmed** only once someone has actually
  signed this off — don't tick it just to get through the form
- If in doubt, leave it unpublished (Save as draft) and check with whoever
  handles clearance before publishing

## Adding a Content Creator

- Only add creators who have said yes to being listed, and check their
  handle/links are still current before publishing
- Leave the framing as "players who also stream" language — don't describe
  us as officially backing their channel or content
- The disclaimer toggle should stay switched on — this is what tells
  visitors the creator's content is their own, not official Army output

## Draft vs Published

Some content types (Players, Content Creators especially) may be set up so
that clicking **Publish** doesn't make it go live immediately — instead it
creates a draft that someone else needs to review and approve first. If you
see a **Save** button instead of, or alongside, **Publish**, that means this
is the case. Don't worry if your change doesn't appear on the live site
right away — it's likely sitting in review, which is intentional for
anything involving real people's details.

## Uploading images

- When a field asks for an image (player photo, event banner, Corps crest),
  click the field and either drag a file in or click to browse your computer
- Only upload images you have the right to use, and only player photos with
  their permission

## If something goes wrong

- Nothing you do here can break the live website permanently — changes go
  through a review step, and previous versions are always kept
- If you're not sure whether to publish something, use **Save** instead of
  **Publish** and flag it to whoever manages the site
- If the page won't load, or Login with GitHub doesn't work, contact
  whoever set up your access — it's likely a permissions issue on their end,
  not something wrong with what you did

## What you don't need to worry about

- You don't need to know what Git, GitHub repos, or code are
- You don't need to install anything
- You don't need to know how the website is built — you're just filling in
  forms
